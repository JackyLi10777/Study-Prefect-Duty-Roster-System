# 跨學年值班、CP Revision 與並行更新整合執行計劃

本計劃把兩個正在實作的任務、本任務的彈性業務需求，以及瀏覽器運算／低負載改善收斂到同一套可驗證流程。
這是待執行及部分執行中的計劃，不代表所列能力已發布。審查發現見
[2026-09-05 review](../audits/20260905-parallel-integration-review.md)；正式版本以
[目前發布狀態](../status/CURRENT_STATUS.md)為準。

## 1. 來源、階段與完成條件

| 階段 | 工作 | 進入下一階段的條件 |
|---|---|---|
| A | 兩個來源任務完成既有手機／PNG／效能更新，記錄 final SHA、差異、測試與剩餘項。 | 來源提交固定；相同大型 patch 只計一次；測試結果可追溯到來源。 |
| B | 從當時最新 origin/main 建立乾淨 codex 分支與 worktree，按功能比對並整合。 | review R1–R9 解決，已存在 PDF／PNG／權限／匯入／編輯功能完整保留。 |
| C | 引入跨學年設定、不可變政策修訂及歷史服務分鐘快照；接入每週排班。 | 設定保存、還原、升年、歷史重看、年終報告與角色限制一致。 |
| D | 建立 CP 活動與指定日期不可值班、排班、修改、發布、恢復、匯出、年報閉環。 | 三個角色同等參與，六席／日、具體日期、185 分鐘與特殊日期完整驗證。 |
| E | 在上述最新狀態整合 browser 工作分配、全站手機與低負載改善。 | 符合原效能／無障礙預算，前後同環境量測，使用中與空閒均無回歸。 |
| F | 各垂直階段獨立 PR、受保護主線合併、發布與生產驗證，最後做交接。 | 乾淨確切提交的證據、受控實體手機／WhatsApp 測試及加密備份恢復演練完成。 |

可以先獨立發布不依賴 B–D 的低負載修正，但不能將它標為整個系統完成。
兩個來源使用中的 worktree 及原始未提交工作區不作整合目的地。
已合併主線的改進直接繼承；尚未合併的成果逐項重建在新主線，禁止重播陳舊巨型提交或整檔覆蓋。
合併不代表已部署，發布狀態只在生產核驗後更新。

## 2. 鎖定的業務規則與資料語義

| 每週業務崗位 | 初始房間／位置 | 初始容量 | 初始開放 |
|---|---|---:|---|
| Assist | 無固定房間 | 1 | 星期一至五 |
| Study Room | Rm 407 | 1 | 星期一至五 |
| Homework Completion | Rm 406 | 2 | 星期一至五 |
| Form 1 Study Group | Rm 202，啟用前可修改 | 2 | 預設關閉；啟用後星期一、三、四 |

- 所有每週崗位預設 `15:40–17:00`，服務分鐘為 **80**，顯示「1 小時 20 分鐘」。
  開放時段與計入服務的時段維持獨立語義，預設連動；取消連動時顯示影響並明確保存。
- 四項業務功能使用穩定語義識別碼，房號只是可編輯標籤；不得以新房號作為歷史 assignment 身份。
  每學年可設定房號、容量、開放星期、啟用狀態與時間。每週另有一次性 override，不回寫學年預設。
- F1 考試前長期關閉；考試日期只作提醒，操作員手動確認開放。重新開網頁保留選擇。
  關閉狀態可見、不排人、不記服務分鐘。
- 政策有可編輯草稿與不可變 revision，保存及啟用顯示影響摘要。恢復預設只還原設定草稿，確認後生效；不修改已發布歷史。
  新學年由既有設定複製成待確認草稿，房號、日期、角色及 F1 狀態重新核對。
- 用受控 Alembic additive migration 保存學年、政策修訂、排班快照及 CP 資料。
  這是新增需求對先前「不做 migration」限制的已確認修訂；不新增學生班級欄位。
- 每次生成保存 effective policy、canonical JSON 雜湊、版本及每席 start/end/service_minutes。
  服務總量用整數分鐘累加，報告只在輸出時格式化。已發布歷史以自身快照讀取，不能被今年設定重新計算。
- 舊資料按原策略及生效日期轉換；無足夠依據者列為待核對，正式年報明確阻止不完整數字，禁止猜成今年 80 分鐘。
  原 policyVersion 作為 provenance 保留，不以 migration 重新冒充原始來源。

## 3. CP Test Revision 完整閉環

- 活動有開始／結束日期，按連續日曆區間列出日期，再由操作員確認實際值班日及排除日；不能直接沿用往年的日期。
- 固定 F1、F2、F3 三組，每組每天兩人。房號每年可改；往年 402／403／404 只作參考，發布前確認。
- Head Study Prefect、Assistant Head Study Prefect、Study Prefect 均加入同一候選池並履行相同職責；新增正式 Head 角色至名冊／匯入／報告。
  週表既有角色限制仍由 weekly 模式處理。
- 個人 unavailable 使用具體日期（年月日），不沿用平日不可值班星期。
- 預設 `08:55–12:00`，**185 分鐘／3 小時 5 分鐘**。可改學年預設及單次活動設定。
- 同一人同一天不可在兩組值班；與週表同日重疊在草稿提示、發布阻止。避免連續日是 soft preference，必要時允許。
- CP 公平排序先看累計 CP 分鐘，再看次數與確定性 tie-break；與 weekly 公平分開，服務總分鐘則合併進年報並列出兩類明細。
- 一次生成整個活動。草稿可保留明確空缺；發布前須填妥或有老師核准的不可用席位。
  發布／調整／撤回／恢復均有版本核對、command_id、完整摘要及持久收據。
- CP 使用完整橫向 PDF 及自適應 PNG；超過 10 個實際日期分頁，每頁重複日期範圍、房間、時間與版本。
  CP 第一版不加入公共 Viewer，保持既有公開分享格式與 Worker KV 契約。

## 4. 共用介面與整合重點

- 沿用 `generate_and_save_draft` 作 weekly 相容入口；新增 policy draft/validate/activate/reset 與 CP generate/publish/adjust/snapshot 的窄介面。
  Official 與 Guest adapter 共用純規則、驗證和 presentation；各自保留正式交易及隔離虛構工作區的儲存語義。
- 同一次 `roster_schedule_snapshot` 建立 canonical `RosterSchedulePresentation`，頁面、PDF、兩種 PNG 及相容分享都從它取完整語義。
  internal fairness audit 也以單次 read transaction 取週表與帳本；不拼接不同時點的讀取。
- 每週 1024×1024 Avatar 與 1600×2000 詳圖均保留完整姓名、正式崗位名稱、各行時間、五個星期與日期、狀態、版本。
  方形 RGB 背景、圓裁安全區、中文姓名最多兩行；48px 文字可讀性不是失敗條件。
  六行是目前預設容量，不是永久硬編碼上限；容量改變後必須完整呈現所有有效席位，不能靜默漏行。
  設定驗證須先確認各匯出格式可完整容納；超出受支持版面時明確阻止啟用並說明限制，不產生缺席位的圖片。
- 正式發布頁優先「生成並下載群頭像 PNG」，提供詳圖、PDF 及繁中／英文；姓名均保持中文。
  draft 只預覽並標記不可派發；Guest 加 PRACTICE、可下載不可原生分享；withdrawn 禁止派發。
- PNG 沿用 90 秒 session/mode 綁定、單次消費、POST ticket-in-body、no-store、nosniff、精確 MIME／signature、單圖 5MiB、渲染並發 2／Guest 1。
  一次性下載與原生分享需在選項變更、重新生成、關閉、登出時清理舊 handler／Blob／預覽。
- 導航、Dialog、保存 Dock、狀態提示及進度共用一致模式；原生 modal 內的進度與錯誤要在同一可互動層。
  收據中的恢復入口必須真正完成該項恢復，而不是導向無法選擇的 vacant assignment。
- 逐個修復 review 問題並先跑對應行為測試，才進下一個功能。移除重複來源、過期回退和舊驗證期待時，要有替代行為證據。

## 5. 瀏覽器運算、手機體驗與低負載

| 位置 | 工作 |
|---|---|
| 瀏覽器 | 已載入候選的搜尋／排序、選取／篩選控制、表單格式與時間差預覽、已授權快照切日、局部畫面更新、音效／動效、Viewer 解密。 |
| 伺服器 | 全域名冊查詢、合資格名單與最終規則驗證、排班搜索、版本及冪等、交易／備份／發布／恢復、服務時數帳與正式年報、確定性 PDF／PNG。 |

- 全域搜尋仍需覆蓋未掛載的人員，不能把當前 20 人的本地篩選誤稱完整搜尋。
  對已授權資料局部操作減少 WebSocket 往返，跨批搜尋使用合併輸入事件的服務查詢。
- 前端試算不作權威資料；保存必須由伺服器重新驗證並回傳確切版本與收據後才顯示成功。
  斷線保留當前頁未保存狀態並明確提示；重新連線先核對身份與版本，禁止偷偷覆蓋。
- 正式名冊不預設寫入 localStorage、IndexedDB 或 Service Worker cache。
  Guest 現有已簽署 sessionStorage 快照按原隔離契約保留。
- 隱藏分頁取消一般 poll timers；返回即核對身份。到期 timer、撤銷處理及伺服器權限檢查持續有效。
  延遲 response 不得復活已 dispose 的監聽器；每個 UI runtime 都有安裝／清理契約。
- 先減少無用工作再評估運算搬移：懶掛載／局部更新、observer 收斂、取消重複事件、字體／CSS 靜態生成與按內容雜湊快取。
  不預設將排班／Pillow 搬到手機；只有量測證明純前端計算阻塞時才引入原生 Web Worker，且有取消與回退。
- 首屏只有目前狀態與主要下一步；周表日視圖、名冊每批 20 人與單人 sheet、次級頁先狀態後詳情。
  涵蓋 Dashboard、週表、歷史／調整、名冊／匯入、Audit、Handover、Settings、Access、Support、內容頁、Public／Viewer。
- 新用戶聲音／音樂預設關閉，首次手勢前音頻 0 B；現有偏好保留。
  GSAP 按需，Material 圖示靜態切換可獨立運作。觸控 ≥44px、輸入字 ≥16px、安全區／鍵盤／橫屏與焦點完整。
- 保留原硬效能預算及 p75 量測，不放寬門檻以消除失敗。
  Idle 比較無瀏覽器、單一可見、單一隱藏、多分頁、20 次進出後的 request、CPU、heap、DOM／listener；不以瀏覽器工作量轉移冒充總能耗降低。

## 6. 測試、發布與交接

- 純規則：每週 80、CP 185 分鐘；未值班／關閉不計；修改後不同版本不重複計；年界與舊政策來源不被新設定污染。
- 跨模式：Admin／Guest／Public／Viewer 能力矩陣；Head 只在 CP 與其他角色同權排班；跨 session、重放、過期、撤回的檔案與分享均拒絕。
- 完整流程：設定→生成→編輯→保存→發布→PDF／PNG→分享→調整→空缺→恢復→撤回→年報，以及匯入、備份恢復、支援報告。
- 競爭與故障：同時編輯、匯出途中發布／撤回、提交成功但備份失敗、網路重試、原生分享取消／不支持、圖片過大與限流。
- 每張圖與 PDF 逐格對照同一快照；語言、長姓名、特殊符號、關閉／空缺／不可用、日期與時間均完整。
- Chromium／WebKit；256px reflow、320、360、390、430、844×390、768×1024、820×1180；深淺、中英、200%字、reduced-motion、forced-colors、鍵盤與軟鍵盤。
- 390×844、DPR2、Fast4G、4×CPU，每項至少 5 次；保留所有 route gates。
  核心編輯操作直接量測 >50ms 長任務；20 次 Dialog／Dock 操作後 heap ≤10MiB、DOM 增量 ≤100、listener 增量 ≤40。
- 精確來源的治理、完整更新驗證、`test-and-audit`、`analyze`、release verification 均過後才合併／發布。
  gate 清單、執行記錄、reader、部署器保持一致，成功 evidence 不隨臨時 workspace 刪除。
- 部署前對帳主機 task、readyz、DB schema、verified backup 和 Worker；新 RC 使用未佔用序號。
  SQLite 變更走已驗證備份與 migration-aware 恢復；只回退程式碼不足以回復資料。
- 涉及 Worker 時先 0% candidate smoke 再提升；政策／NiceGUI-only 不重發 Worker。
  原子 bundle 切換後核驗 healthz／readyz、身份／WebSocket、各角色及主要工作流程。
- 實體 Android、iPhone Safari 和受批准校內 WhatsApp 群人工確認下載／換圖／分享／更新替換，
  完成受監督的加密備份恢復演練後，才更新 production status 及獨立 closeout PR。

目前下一步是完成 A／B 的來源與語義收斂；C／D 是已確認的產品需求，尚不能因手機或 PNG 測試通過而標為完成。
