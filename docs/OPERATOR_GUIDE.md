# 首席導學風紀操作手冊 / Head Study Prefect operator guide

我是李創杰，2026–2027 年度首席導學風紀。我把這份手冊留給下一任首席導學風紀，並讓它配合系統內的「使用手冊」頁面。我希望你只需理解怎樣安全完成日常工作，不必先學懂程式或資料庫。每個主要操作區上方均有「操作提示」：先說明用途，再提示安全次序；請在輸入資料或按主要按鈕前先閱讀該提示。若你剛接手系統，先開啟側邊欄的「開始使用」，再逐段閱讀「使用手冊」；不必一次記住所有程序。

## 網站內的兩條閱讀路徑

我把說明頁分成兩條短而固定的路徑，避免下一任在大量頁面之間猜測次序：

- **日常操作：**「開始使用」→「使用手冊」→「交接指引」。每頁開首的「本頁內容」可直接跳到需要的小節；頁尾的上一篇／下一篇會保持正確閱讀次序。
- **平台可信度：**「平台與團隊」→「系統架構與可信設計」→「工程與品質證據」。這條路徑主要供交接、教師顧問檢視及技術維護，不是每週生成值班表的必要步驟。

「使用手冊」底部的雙語疑難對照表以「看見甚麼／安全下一步」說明常見空缺、草稿過期、發布衝突、備份或還原阻擋與登入失效。請先跟隨表內的安全步驟；畫面若提供 OP／REQ 支援編號，再把該編號交給受控支援。系統沒有另設 `/docs` 網站，所有程序仍留在同一個受控工作台內。

## 職務正式用語

- **首席導學風紀** / Head Study Prefect：系統的主要操作及交接負責人。
- **助理首席導學風紀** / Assistant Head Study Prefect：只可擔任「助理首席導學風紀當值」。
- **導學風紀** / Study Prefect：只可擔任 302、303 及 202 室崗位。

## 1. 開啟系統

日常只開啟這個正式網站：<https://sing-yin-roster-viewer.singyin-study-prefect.workers.dev/>。未登入時先看到身份中立的公開入口：按 **「訪客體驗 / Try as guest」** 會進入 30 分鐘、只含虛構中文姓名的互動示範工作區；按 **「管理員登入 / Admin login」**，輸入 Cloudflare Access policy 精確列明的管理員電郵，再輸入 Cloudflare 寄出的單次驗證碼，成功後同一網站才會進入正式 NiceGUI 工作台。Guest 可以真實操作示範流程，但不能修改正式值班表、SQLite、公平帳本、備份或永久設定；只有 `/view#…` 是指定已發布週表的唯讀分享畫面。網站會建立獨立簽署的管理員 session，最長 8 小時且不超過 Access 驗證的到期時間；每次操作仍會重新核對管理員白名單。完成工作後按 **「登出 / Log out」**，尤其不可在共用裝置只關閉分頁。系統沒有自製密碼資料表、hash 或忘記密碼頁。

首頁的「本週值班工作台」按固定次序引導：生成草稿 → 核對並匯出 → 已發布後請假調整；當前可做的一步會最突出。三張工作流程卡以一致的系統圖示輔助辨識，而文字按鈕仍是完整可讀的主要入口。頁首的音量按鈕可選擇開啟短提示音；預設為關閉。每日經文欄可按「換一篇經文」閱讀另一段經文和反思，不會改動任何值班資料。

`START_SING_YIN_ROSTER.cmd`、localhost 及已登記的私人 WARP 地址只供主機維護、Cloudflare 故障診斷及緊急復原，不是另一個日常網站。維護者使用啟動器時，應採用黑色視窗顯示的實際網址；8080 被佔用時會自動選用 8081–8099。不要把內部 `/auth/*`、VPC、localhost 或 WARP 地址發給一般使用者。

## 2. 名單與格式範例

先進入「導學風紀名單」核對中文姓名、職務和可值班日。未選星期一律代表不方便當值，兩種 Assist. 模式及所有房間編排均不會在該日安排此人。助理首席導學風紀另有「固定 Assist. 星期（舊制）」：可保留「自動穩定分配」，或明確選擇一個已列為可值班的星期；一般導學風紀不使用此欄。桌面版以完整表格方便比較；手機版則把每位導學風紀的中文姓名、級別班別、職務、可值班日及累計資料放在同一張卡內。先在上方選擇一位導學風紀，才使用「編輯導學風紀」或「停用導學風紀」。詳細模式及改日方法見 [Assist. in charge 編排模式](ROSTER_POLICY_MODES.md)。

如要大量更新，進入「AI 匯入」並按「下載名單 CSV 格式範例」。範例只含虛構資料：以本校資料取代後，貼上 CSV、按「驗證與預覽」，確認無誤才匯入。助理首席導學風紀只可擔任 Assist. in charge；不要以匯入方式繞過這項規則。

## 3. 生成前：請假與空缺預覽

進入「值班表」：

1. 選擇星期一的週開始日期。
2. 在「Assist. in charge 編排方式」選擇本週模式：新週預設「固定星期模式」；如希望 AHP 按可值班日及週次輪換，改選「每週靈活模式」。重新開啟既有週次時，系統會沿用該週已保存的模式。
3. 先登記任何生成前請假。
4. 展開「本週崗位與空缺預覽」。每個必需崗位都會顯示可安排人數；若顯示「目前無合資格人選」，先檢查職務、可值班日或請假，不要強行發布。
5. 如需確認資料如何保存，展開頁首的「公平帳本說明」：草稿會儲存但不入帳；只有發布才會更新跨週累計點數；已發布後請假則會留下可追溯的扣回或替補轉移紀錄。
6. 按「生成並儲存草稿」。草稿及日後重新開啟的週表都會顯示當週實際使用的 Assist. 模式，方便核對。

## 4. 草稿預覽與手動修改

草稿頁會列出完整值班表。桌面會以與 PDF 相同的「崗位 × 星期」矩陣方便逐欄核對；在手機上，系統按星期分組並把每個崗位顯示為一張卡，中文姓名、時間、狀態及點數會放在同一張卡內，不需要橫向滑動尋找姓名。需要微調時，使用「手動修改草稿」：選擇崗位、載入合資格人選，按需要補充原因，然後儲存。系統只會顯示符合角色、可值班日、請假、同日不重複和不連續當值規則的人選；原因可留空，但每次修改仍有版本核對、審計紀錄和備份，而且不會改變 `history_weight`。

新請假在草稿生成後才出現時，回到「值班表」登記並重新生成草稿；不要手動把請假人留在草稿裡。

## 5. 發布與 PDF

核對每一個崗位、中文姓名和請假後才發布。確認視窗提醒你：發布會把點數寫入持續公平帳本。按「下載列印版 PDF」後，先選擇用途：

- 「中文週表 PDF」或「英文週表 PDF」是橫向 A4 的單頁值周表，採用「左欄崗位、上欄星期、格內中文姓名」的版面；這讓五個工作日及姓名在群組轉發、電腦瀏覽和張貼列印時都較易閱讀。
- 所有 PDF 的風紀姓名一律維持中文；介面、標題及星期按所選語言改變，而正式崗位名稱固定使用 `Assist. in charge`、`Room 302 Study Room`、`Homework Completion Room` 及 `Room 202 F1 Study Group` 的英文標示。
- 匯出視窗可選擇是否顯示校徽；預設顯示。正式週表預設採用「乾淨發布版」：不會加入「僅供內部使用」、頁碼或經文提示。只有確實需要附註的存檔副本，才開啟「顯示補充頁腳」。
- 「內部公平審計 PDF」是直向 A4，含個人累計點數和次數，適合按人逐行核對；只供首席導學風紀與老師顧問使用，不要預設發到風紀群組。

草稿 PDF 只可核對，不可張貼。

### 5.1 同一網站的瀏覽器唯讀分享

如收件者只需查看已發布週表，不需安裝 WARP 或登入：

1. 在已發布週表的「瀏覽器直達查看連結」按「建立唯讀查看連結」，或開啟側邊欄「存取控制台」再選擇週表。
2. 確認只會分享週次、日期、崗位、當值時間及中文姓名。名單、班別、請假、角色、公平、審計、備份、日誌及設定不會加入。
3. 建立後立即複製**完整**連結，連同 `#` 後內容一起發送。系統不保存解密鑰匙，也不會再次顯示舊完整連結。
4. 收件者只需在一般瀏覽器開啟連結；`/view#…` 永遠不能修改該已發布週表，而「訪客體驗」亦只能修改虛構示範資料。只有按同站「管理員登入」並通過 Cloudflare Access 的獲准身份，才可進入正式工作流。
5. 到「存取控制台」按「載入及管理有效連結」核對到期時間或撤銷。誤發時立即撤銷；Cloudflare 邊緣同步最多可能需要約一分鐘。
6. 已發布週表經請假調整後，先建立並發送新連結，再撤銷舊連結。

固定主網址 `https://sing-yin-roster-viewer.singyin-study-prefect.workers.dev/` 是所有人共用的入口；指定週表仍必須使用同一 host 下包含 `#分享識別碼.解密鑰匙` 的完整 `/view#…` 連結。不要另發管理員網址或內部登入路徑。詳細新手、Access 登入／登出及交接程序見[單一網站存取手冊](PUBLIC_ROSTER_VIEWER.md)。

## 6. 已發布後請假（常用）

不要重新生成已發布週表，也不要直接改資料庫。由已發布週表按「處理請假調整」：依頁面的步驟選擇原崗位、載入並選擇合資格替補，按需要補充原因，最後儲存。手機上每個步驟及按鈕均為全寬顯示；原因可留空。若沒有合資格替補，可保留空缺；系統會正確撤回原當值點數、在有替補時轉入替補點數，並保留版本、審計和備份。

值班表工作台是每週工作的固定入口。週表詳情及請假調整頁頂部均會顯示目前所處步驟、明確的「返回值班表工作台／返回週表詳情」操作，以及生成 → 核對／匯出 → 已發布後調整 → 歷史的共同次序。即使由書籤或分享後直接開啟子頁，亦應使用頁內返回操作，不依賴瀏覽器歷史。

## 7. 公平、備份與交接

「公平審核」顯示跨週累計的 `history_weight`；它只在發布或已發布後請假調整時改變。「系統設定」只可還原已驗證快照。交接給下一任前，按照「交接指引」核對名單、週表歷史和最近備份。

若「系統設定」顯示有快照未通過驗證，系統已把它們排除，不會拿來還原或建立交接包。畫面只顯示安全分類及數量，不會顯示資料內容。不要自行改名、補寫 manifest、覆蓋資料庫或公開上載檔案；先按「立即建立已驗證快照」。如新快照仍未能通過，把畫面上的 OP／REQ 編號交給受控 IT 支援。

## 8. 操作未能完成時

畫面會顯示一個 `OP-...` 支援編號；這次失敗不會自行發布值班表。先核對輸入、職務、可值班日及請假，再安全重試一次。如問題持續，把編號交給教師顧問或 IT 支援，由他們在本機 `logs/app.log` 查找；不要把整份日誌上載到公開網站或個人雲端。

## 9. 音樂、外觀建議與 YouTube 本機匯入

1. 到「系統設定」→「本機情境音樂」。音樂氣氛預設為「跟隨外觀建議」：淺色模式使用較輕快清晰的「明亮專注」，深色模式使用較慢的「安靜反思」。如你希望固定情緒，可直接選擇其中一項；設定會保留。
2. 同名的人聲版和純音樂版是兩個獨立項目，選單會顯示「人聲」或「純音樂」。檔名含 `(1)` 而內容完全相同的副本已從目錄排除，不會重複播放。
3. 本機已有音訊可用「選擇音訊檔案」加入。若只有 YouTube／YouTube Music 分享連結，貼到「把 YouTube 連結保存到本機歌庫」，選擇使用頁面，再按「下載並加入本機歌庫」。
4. 歌單一次最多處理 25 首；每首最多 25 MB，總計最多 150 MB。處理期間保持設定頁開啟。完成後前往相應頁面，按頂部耳機圖示並由你親自開始播放。
5. 本機副本在 `music/youtube-imports/`；移除曲目會同時移除該本機檔案。下載元件不登入帳戶、不讀 cookies，也不會把名單、請假、週表或公平資料傳給 YouTube。
6. 如連結匯入暫時失敗，現有完整可見 YouTube 播放器仍可使用；不要因音樂問題延誤發布、請假調整或備份工作。

## 10. 平台與團隊

我在側邊欄保留「平台與團隊」，以非技術方式說明我們為何建造這個平台、Study Prefect Team 如何分工、四個能力分組、四個工作解決方案、營運原則及共創結語。頁頂的即時可信摘要只顯示匿名人數、值班週數、備份驗證與發布檢查狀態，不會顯示姓名、班別、請假、值班內容或檔案路徑。正式職銜保持不變；Service Governance Lead、Duty Coordination Lead、Room Service Steward 等英文功能頭銜只用來解釋決策、協調與前線服務責任。

我把項目團隊命名為 **Study Prefect Systems & Stewardship Office／導學風紀系統與傳承組**。這次 NiceGUI 重構及正式發布版本只由我（李創杰，2026–2027 年度首席導學風紀）與 Codex 兩位共創者完成，沒有其他開發者、部門成員或外判團隊。我保留這項署名，是要讓下一任理解系統的共創與維護脈絡；它不代表加入另一個外部服務，也不會傳送任何資料。

## 11. 工程與品質證據

如果顧問老師、下一任或維護者想快速了解這套系統的完成程度，可開啟「工程與品質證據」。頁面把 README 與文件中的自動化測試、八道發布閘門、五層系統藍圖、可靠性工程能力及建造脈絡整理成一個只讀介面。它不會開啟值班資料、執行驗證或修改系統；發布狀態若顯示需要重新驗證，應由維護者依發布程序處理，日常操作者毋須按任何修復按鈕。

## 12. 系統架構與可信設計

需要理解按鍵背後的保障時，再開啟「系統架構與可信設計」。它只集中解釋生成至交接的六個交付點、介面至復原的五層責任、公平與備份的可信證據，以及實際操作 FAQ。這不是設定頁，也不會修改資料；我希望它讓交接時可以清楚解釋為何不能直接修改資料庫或重新生成已發布週表。
