# 首席導學風紀操作手冊 / Head Study Prefect operator guide

本手冊配合系統內的「使用手冊」頁面。它說明怎樣完成日常工作，而不是要求使用者理解程式或資料庫。每個主要操作區上方均有「操作提示」：先說明用途，再提示安全次序；請在輸入資料或按主要按鈕前先閱讀該提示。若剛接手系統，先開啟側邊欄的「開始使用」，再逐段閱讀「使用手冊」；不必一次記住所有程序。

## 職務正式用語

- **首席導學風紀** / Head Study Prefect：系統的主要操作及交接負責人。
- **助理首席導學風紀** / Assistant Head Study Prefect：只可擔任「助理首席導學風紀當值」。
- **導學風紀** / Study Prefect：只可擔任 302、303 及 202 室崗位。

## 1. 開啟系統

在系統資料夾雙擊 `START_SING_YIN_ROSTER.cmd`。瀏覽器會自動開啟；如沒有，前往 `http://127.0.0.1:8080`。首頁的「本週值班工作台」按固定次序引導：生成草稿 → 核對並匯出 → 已發布後請假調整；當前可做的一步會最突出。三張工作流程卡以一致的系統圖示輔助辨識，而文字按鈕仍是完整可讀的主要入口。頁首的音量按鈕可選擇開啟短提示音；預設為關閉。每日經文欄可按「換一篇經文」閱讀另一段經文和反思，不會改動任何值班資料。

啟動器會先重用已在執行的系統；不要因為瀏覽器暫未開啟而連續雙擊。黑色啟動視窗會顯示真正可用的網址。若 8080 已被其他程式使用，系統會選用 8081–8099 之間的可用埠，因此應使用視窗顯示的完整網址，而非自行猜測。所有網頁操作均在受控本機進行；不要把資料庫、PDF、備份、截圖或日誌傳到公開網站。

## 2. 名單與格式範例

先進入「風紀名單」核對中文姓名、職務和可值班日。桌面版以完整表格方便比較；手機版則把每位風紀的中文姓名、級別班別、職務、可值班日及累計資料放在同一張卡內。先在上方選擇一位風紀，才使用「編輯風紀」或「停用風紀」。

如要大量更新，進入「AI 匯入」並按「下載名單 CSV 格式範例」。範例只含虛構資料：以本校資料取代後，貼上 CSV、按「驗證與預覽」，確認無誤才匯入。助理首席導學風紀只可擔任 Assist. in charge；不要以匯入方式繞過這項規則。

## 3. 生成前：請假與空缺預覽

進入「值班表」：

1. 選擇星期一的週開始日期。
2. 先登記任何生成前請假。
3. 展開「本週崗位與空缺預覽」。每個必需崗位都會顯示可安排人數；若顯示「目前無合資格人選」，先檢查職務、可值班日或請假，不要強行發布。
4. 如需確認資料如何保存，展開頁首的「公平帳本說明」：草稿會儲存但不入帳；只有發布才會更新跨週累計點數；已發布後請假則會留下可追溯的扣回或替補轉移紀錄。
5. 按「生成並儲存草稿」。

## 4. 草稿預覽與手動修改

草稿頁會列出完整值班表。桌面會以完整表格方便逐欄核對；在手機上，系統按星期分組並把每個崗位顯示為一張卡，中文姓名、時間、狀態及點數會放在同一張卡內，不需要橫向滑動尋找姓名。需要微調時，使用「手動修改草稿」：選擇崗位、載入合資格人選、填寫原因，然後儲存。系統只會顯示符合角色、可值班日、請假、同日不重複和不連續當值規則的人選；每次修改都有審計紀錄和備份，但不會改變 `history_weight`。

新請假在草稿生成後才出現時，回到「值班表」登記並重新生成草稿；不要手動把請假人留在草稿裡。

## 5. 發布與 PDF

核對每一個崗位、中文姓名和請假後才發布。確認視窗提醒你：發布會把點數寫入持續公平帳本。按「下載列印版 PDF」後，先選擇用途：

- 「中文週表 PDF」或「英文週表 PDF」是橫向 A4 的單頁值周表，採用「左欄崗位、上欄星期、格內中文姓名」的版面；這讓五個工作日及姓名在群組轉發、電腦瀏覽和張貼列印時都較易閱讀。
- 所有 PDF 的風紀姓名一律維持中文；只有介面、標題、星期與崗位標籤按所選語言改變。
- 「內部公平審計 PDF」是直向 A4，含個人累計點數和次數，適合按人逐行核對；只供首席導學風紀與老師顧問使用，不要預設發到風紀群組。

草稿 PDF 只可核對，不可張貼。

## 6. 已發布後請假（常用）

不要重新生成已發布週表，也不要直接改資料庫。由已發布週表按「處理請假調整」：依頁面的三個步驟選擇原崗位、載入並選擇合資格替補、填寫原因，最後儲存。手機上每個步驟及按鈕均為全寬顯示；如未填寫原因，系統會停在原因欄提示補充，不會寫入任何調整。若沒有合資格替補，可保留空缺；系統會正確撤回原當值點數、在有替補時轉入替補點數，並保留記錄和備份。

## 7. 公平、備份與交接

「公平審核」顯示跨週累計的 `history_weight`；它只在發布或已發布後請假調整時改變。「系統設定」只可還原已驗證快照。交接給下一任前，按照「交接指引」核對名單、週表歷史和最近備份。

若「系統設定」顯示有快照未通過驗證，系統已把它們排除，不會拿來還原或建立交接包。畫面只顯示安全分類及數量，不會顯示資料內容。不要自行改名、補寫 manifest、覆蓋資料庫或公開上載檔案；先按「立即建立已驗證快照」。如新快照仍未能通過，把畫面上的 OP／REQ 編號交給受控 IT 支援。

## 8. 操作未能完成時

畫面會顯示一個 `OP-...` 支援編號；這次失敗不會自行發布值班表。先核對輸入、職務、可值班日及請假，再安全重試一次。如問題持續，把編號交給教師顧問或 IT 支援，由他們在本機 `logs/app.log` 查找；不要把整份日誌上載到公開網站或個人雲端。

## 9. 系統架構與共創

側邊欄的「系統架構與共創」以非技術方式展示系統如何分工：介面負責提示與語言，校規核心負責排班限制，工作流負責 SQLite 交易、公平帳本與審計，備份層負責校驗和受控還原。這個頁面不是設定頁；它讓交接時可以清楚解釋為何不能直接修改資料庫、重新生成已發布週表或把資料外傳。

頁面亦保留本系統的共創結語。項目團隊名稱為 **Study Prefect Systems & Stewardship Office／導學風紀系統與傳承組**；這次 NiceGUI 重構及正式發布版本只由李創杰（2026–2027 年度首席導學風紀）與 Codex 兩位共創者完成，沒有其他開發者、部門成員或外判團隊。這項署名用於交接與維護脈絡，不代表加入另一個外部服務，也不會傳送任何資料。
